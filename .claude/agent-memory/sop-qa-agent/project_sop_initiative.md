The project is converting a single messy "HR Front Desk Standard Operating Procedures" source document (many unrelated bullet-point duties) into individual, template-conformant SOPs, one topic at a time. A `sop-writer` agent drafts each SOP into `/media/jovanni/STORAGEV2/Workspace/IronForge/SOP/`, and this QA agent reviews it.

Key files:
- Approved template: `SOP/Standard Operating Procedure TEMPLATE 2026.dotx` (plain-text conversion cached at `/home/jovanni/tmp_sop_convert/Standard Operating Procedure TEMPLATE 2026.txt`).
- Raw source material: `SOP/Front Desk Standard Operating Procedures.doc` (plain-text conversion cached at `/home/jovanni/tmp_sop_convert/Front Desk Standard Operating Procedures.txt`). This is a flat list of ~20 unrelated front-desk duties (mail, parking tags, ID badges, exit interviews, orientation, onboarding, AWS e-forms, Annual Service Awards, background checks, purchasing, etc.) — no topic gets its own dedicated heading beyond a short bullet, so drafts are often assembled from small, scattered excerpts.
- Assignment map / review checklist lives in `SOP/SOP_Agent_Instructions.md`.

Drafts completed so far (as of 2026-08-31): `SOP/Exit Interview.md` (sourced from "Exit Interview (Metrics)" section), `SOP/Hotel Reservations.md` (sourced from two unrelated sections: "Orientation Scheduling Twice a Month" and "Annual Service Awards" — there is no dedicated "Hotel Reservations" section in the source).

**Why:** understanding that source material is fragmentary/flat explains why individual drafts look thin or stitched-together from unrelated bullets — that's an artifact of the source, not sloppy drafting.
**How to apply:** when reviewing future SOPs from this same source doc, expect sparse/scattered sourcing to be normal, check the writer's own "Open Questions / Gaps section for disclosure, and cross-check named-individual role/title gaps and terminology against sibling drafts already produced (see [[feedback-sop-qa-sparse-source]] and [[reference-sop-file-locations]]).
